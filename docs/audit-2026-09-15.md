# TaskSpindle audit — 2026-09-15

Audited: `main`-line source at 53a1328 (`dispatch-policy` branch, version 0.5.0, schema 11), the
live deployment on this host, and the Codex-side consumer skill that drives it. Method: three
parallel read-only code audits (core state, worker/provider runtime, tests/CI/docs/web/CLI), a
read-only inspection of the production SQLite state and task directories, and spot verification
of every headline claim against the source. Every finding cites file and line as of 53a1328.

The tier-1 remediation recorded at the end of this document was applied on branch `audit-tier1`.

Two observations that only the live data could show:

- **Every Grok `ACP_HANDSHAKE_FAILED` had the same, permanent cause.** `agent-1.stderr` in each
  task directory reads `sandbox profile resolve failed: hook source path contains a symlink
  component ... ~/.grok/hooks/guard-bash.json`. TaskSpindle reported it to Codex as
  `"The provider turn failed."` with empty `details` and `retryable: true`. The cause was on disk
  the whole time and never surfaced. (Tier-1 item T5.)
- **Timeouts are the leading failure and are self-inflicted.** Reviews average 220 s and are
  routinely started with a 300 s budget. Nothing on the server side reports elapsed time or
  offers a partial result at timeout, so the coordinator learns only that the turn failed.

## 2. Findings, ranked

Severity: **S1** breaks a documented guarantee or loses work; **S2** wrong behaviour with a
workaround; **S3** brittleness or drift; **S4** hygiene.

### S1

1. **CI is red.** `.github/scripts/mcp_smoke.py:19` hard-codes `EXPECTED_TOOLS = 18`; the server
   registers 19 (`server.py:59-78`) since `dispatch_policy` landed. Every push fails the smoke
   step. *Fixed in T1.*
2. **Read-only tools dispatch work.** `list_tasks`, `task_status`, `task_result`, `usage_report`
   and `list_repository_policies` carry `readOnlyHint` (`server.py:47-57`) but run
   `Orchestrator._cycle()` (`orchestrator.py:316-327`), whose `finally` calls
   `dispatch_queued()`: leases are taken and systemd units started from a status poll. The same
   `finally` replaces the tool's real exception with any dispatch error, so a client sees
   `INTERNAL` instead of, say, `GRANT_MISSING`. *Fixed in T2.*
3. **`state_version` moves without a transition.** `Store.update_task` bumps it on every call
   (`store.py:1076`), including unit assignment at dispatch (`orchestrator.py:1145`), workspace
   bookkeeping (`:930`) and cleanup state (`:1767, :1838, :1863`). A Codex session that read a
   version from `task_status` can be refused with `STALE_STATE_VERSION` because its own poll
   dispatched the task. `docs/tools.md:319` and `docs/architecture.md:54` promise the opposite.
   *Fixed in T3.*
4. **Interrupted tasks cannot be resumed.** `INTERRUPTED` is not in `TERMINAL_STATES`
   (`models.py:66`), so the worker exits 1 (`runner.py:1746`); units run without `--collect`
   (`units.py:232`) so the failed unit stays loaded; `reset_failed` runs only from the
   active-state sweep (`recovery.py:249`) and from cleanup (`orchestrator.py:1828`); the unit
   name is the task id (`units.py:280`). The next `continue_task` collides with the loaded unit
   and fails `UNIT_START_FAILED`. *Fixed in T4.*
5. **Handshake and spawn failures hide their cause.** See §1. `runner.py:546-640` builds the
   failure from the RPC error only; the agent's stderr is written to disk and never read. In the
   same region, a `_Failure` raised by `_check_initial_auth_context` (`runner.py:548, 788-791`)
   replaces the original refusal, so the provider status row is not updated for a real refusal.
   *Fixed in T5.*
6. **Dashboard read routes are unguarded.** Of 17 routes (`web/app.py:671-687`) only the five
   policy routes check peer and `Host`. `/api/tasks/{id}` (full prompt, worker log tail),
   `/api/tasks/{id}/diff`, `/api/usage`, `/api/providers`, `/api/doctor`, `/api/overview` and
   `/api/policy/history` accept any `Host`, so a hostile page can DNS-rebind to the loopback
   port, and `--host 0.0.0.0` publishes every repository's prompts and diffs to the LAN. No
   security headers are sent. The behaviour is pinned by `tests/test_policy_web.py:356`.
   *Fixed in T6.*
7. **Secrets on the process table.** Worker environment goes to `systemd-run` as
   `--setenv=NAME=VALUE` (`units.py:242`), including `api_key` profile secrets
   (`orchestrator.py:272-296`, `units.py:322`). They are readable in `/proc/<pid>/cmdline` and
   via `systemctl --user show <unit> -p Environment`. `docs/configuration.md:101-104` says the
   value is never stored, logged or returned. *Fixed in T7.*
8. **`record_integration` is not atomic.** ACCEPTING → ACCEPTED is two commits with no journal
   row and no `expected_state_version` on the second (`orchestrator.py:1662-1677`). A concurrent
   reconcile from another MCP process or the dashboard sees ACCEPTING with no unit and no
   journal, treats it as an aborted accept, and pushes the task back to RESULT_READY after the
   integration already landed.
9. **Permission gate is allow-by-default.** `PermissionPolicy` denies only `edit`, `delete`,
   `move`, `execute` when writes are disallowed (`acp_client.py:77, 152`); ACP's `other`,
   `search` and `think` kinds pass. Only the provider-specific layers (Claude `plan` mode, Grok
   `--sandbox read-only`, Antigravity bwrap) close the gap, and a configured second-class
   profile has none of them. No layer confines write paths for Claude or configured profiles;
   the only path-aware policy, `AgyPermissionPolicy`, is unreachable from the runner
   (`runner.py:564` routes every `agy` profile to `AgyCliWorker`). A symlink inside the
   worktree pointing outside it defeats both post-hoc checks (`scope_violations`,
   `_check_root`) because git never sees the write.

### S2

10. **Vendor pins are exact strings.** Antigravity must report exactly `1.1.26`
    (`agy_cli_adapter.py:22, 78`); `doctor` requires the prefix `grok 1.0.13` (`doctor.py:57`);
    the Claude adapter must be exactly `@agentclientprotocol/claude-agent-acp 0.70.0`
    (`__init__.py:6-7`, `setup.py:210-215`). Every vendor release breaks `setup`/`doctor`
    until TaskSpindle releases. The operator's runtime already drifted (§1).
11. **Antigravity provider state is inferred from stderr prose.** `agy_cli.py:60-114` lowercases
    stderr and substring-matches phrases such as `rate limit`, `unauthorized`, `unknown model`;
    `access_checks.agy_run` (`access_checks.py:93`) feeds it stdout as well. The result is
    trusted as durable account evidence by `limits.classify_acp_error` (`limits.py:394-404`).
12. **Delegation heuristic denies ordinary edits.** `_DELEGATION_WORDS =
    \b(?:subagent|agent|team)\b` is searched against the whole tool-call title
    (`acp_client.py:70, 125`). `Edit src/agent.py` or `Run pytest tests/test_agent.py` is denied
    and recorded as `DELEGATION_ATTEMPT`. Two live warnings match this shape.
13. **`ROOT_MUTATION` fires when a sibling task is accepted.** The root snapshot compares HEAD
    (`repos.py:234`, `runner.py:1559`), so accepting task A flags every other in-flight task in
    the repository, each of which is then blocked at `_accept_gates` until a manual
    acknowledgement bound to its exact revision (`orchestrator.py:1931-1963`). The advertised
    four-per-provider concurrency (`docs/concurrency.md`) therefore serializes acceptance in one
    repository behind operator acks. Thirteen live warnings.
14. **`require_diff_retrieved` passes vacuously** when `diff_size` is `NULL`
    (`service.py:719-731`); `accept_task` is saved by its digest equality check but
    `record_integration` has no digest (`orchestrator.py:1652`).
15. **A relocated repository strands an accepting task.** Repository identity falls back to
    `display_path or common_dir.parent` in four copies (`orchestrator.py:541, 657`,
    `accept.py:169`, `runner.py:1574`); `find_repository` keys on the absolute common dir
    (`store.py:962`). If the repo moves while a task is ACCEPTING the accept unit fails, recovery
    raises inside `_identity_for`, and the task lands in `RECOVERY_AMBIGUOUS` whose only legal
    exits are RESUMING (which re-enters the same failure) and CANCELLING.
16. **`run_worker`'s `finally` can mask the outcome and leak the lease.** `runner.py:443-462`
    awaits the heartbeat task (only `CancelledError` is suppressed), then calls
    `hybrid_recovery.finish`, `provider_recovery.finish`, `finish_quota_retry` unwrapped, and
    `release_lease` last. `AgyCliWorker.prompt` has the same shape: `_stop_process` can raise
    `AGY_CLI_STOP_FAILED` before `last_result` is set (`agy_cli.py:151-155, 589-596`), dropping
    the captured turn.
17. **Verification timeout is per command and runs `shell=True` in the operator's repository.**
    `integration.py:206-215` applies `timeout_s` to each command; `accept.py:120` passes up to
    1800 s. N commands can hold the root for N × 1800 s, from an unvalidated list supplied at
    `start_task`.
18. **Git edge cases.** Submodules are neither populated nor detected; an empty cherry-pick is
    reported as `CONFLICT:` with no paths (`integration.py:157-170`, `accept.py:186`);
    `--no-renames` is used when collapsing (`worktrees.py:120-124`) but not when writing the
    diff artifact (`:145-156`); `run_git`'s 60 s default (`repos.py:75`) raises
    `TimeoutExpired`, not `GitError`, so it surfaces as `INTERNAL`; the whole diff is buffered
    in memory; `abort_staged` unlinks files but not directories (`integration.py:308-310`);
    `commit_landed` assumes a single-parent HEAD (`integration.py:269`).
19. **Diff artifacts are not reproducible.** `worktrees.py:141` claims byte-identical output, but
    `run_git` passes `HOME` through without `GIT_CONFIG_GLOBAL=/dev/null` (`repos.py:35-42, 91`)
    and honours `.gitattributes`, so `diff.algorithm`, `diff.noprefix` and friends change the
    digest that receipts are keyed on.
20. **Snapshot refs leak forever.** `refs/taskspindle/snapshots/<id>` is written with an
    unstored random id (`worktrees.py:213`, `orchestrator.py:871`) and `delete_task_refs` only
    removes `refs/taskspindle/<task_id>/` (`worktrees.py:237`). Every snapshot review pins a
    commit of the operator's working tree in the operator's repository.
21. **Five ISO-8601 parsers, two policies for naive timestamps.** `limits._parse_iso` and
    `recovery._parse` assume UTC; `quota._time`, `provider_recovery._time` and
    `grok_checks.parse_time` return `None`. The same `reset_at` row can unblock dispatch
    (expired → unknown) while hybrid recovery holds it as `provider_reset_pending`.
22. **`ReviewTarget.paths` is unvalidated** (`models.py:216`) unlike `path_prefixes`
    (`models.py:280-285`), and goes straight to `git add -A --` in the root.
23. **CLI bypasses the recovery gate.** `taskspindle providers --retry-next` resolves
    `evidence_revision` itself (`cli.py:487-497`) whereas the MCP tool demands the caller pass
    one it has inspected (`server.py:238-247`). The CLI reimplements arm/revoke instead of
    calling `Orchestrator.provider_recovery`.
24. **CLI drift.** `taskspindle usage --group-by role` rendered an indistinguishable table
    (`cli.py:597-600`); the `usage_report` tool docstring omitted `role` (`server.py:465`);
    `main()` fell through to `_accept` for any unmatched subcommand (`cli.py:227`); `usage` and
    `providers --check` open the store read-write and auto-migrate (`cli.py:578, 360`).
    *Docstring, table and fall-through fixed in T8; auto-migration left for tier 2.*

### S3 — brittleness

- `boot_id()` falls back to the literal `"unknown"` (`units.py:37-40`), which defeats reboot
  detection when two boots both read it.
- `git ≥ 2.38` is checked only by `doctor` (`doctor.py:50`); at the point of use an old git
  turns into an opaque `GIT_FAILED` accept abort.
- Version parsing by regex or string surgery: `doctor._version` strips every `v`
  (`doctor.py:85-95`); `grok_checks.py:249` full-matches one exact format; `access_checks.py:240`
  requires `\d{1,4}\.\d{1,4}\.\d{1,4}`.
- Claude plan tiers are an allowlist of `pro` and `max` (`providers.py:682-692`); the session
  file path reverse-engineers Claude Code's project-dir mangling (`usage.py:239-245`); eighteen
  `GROK_<VENDOR>_<SOURCE>_ENABLED=false` switches are synthesized against a private namespace
  (`providers.py:98-102`); `launch_command` silently returns the command unchanged when it
  cannot find the literal `agent` token to insert `--sandbox read-only` (`providers.py:502-506`).
- Fixed sleeps in the turn's critical path: 2 s Grok late-update grace (`runner.py:87`), eight
  250 ms polls for the Claude session file (`runner.py:1324`).
- `_group_running` scans all of `/proc` every 10 ms for up to 0.5 s on every Antigravity
  teardown (`agy_cli.py:123-135`); `prepare_launch` walks the workspace three times on the event
  loop and emits nine deny rules per directory (`agy_cli_policy.py:72-90, 163-166`).
- SQLite `busy_timeout` is 10 s while `start_task` holds `BEGIN IMMEDIATE` across policy load,
  quota evaluation, native-overage snapshot and recovery admission (`orchestrator.py:701-772`).
- `Store.transaction()` nesting silently keeps the outer transaction alive after an inner block
  raised and was caught (`store.py:853-872`); `_depth` is per-instance and not thread-safe;
  `capabilities(check_providers=...)` opens a fresh `Store` per provider thread and re-runs
  `migrate()` each time (`orchestrator.py:482-497`).
- Eleven forward-only migrations; the only downgrade covers migration 4 alone
  (`store.py:911-933`); `Store.open` always migrates, so any older runtime that opens the
  database upgrades it. `insert_task` inspects `PRAGMA table_info` on every insert
  (`store.py:1013-1018`).
- Unit properties set memory limits only (`units.py:51-58`): no `CPUQuota`, `TasksMax`,
  `RuntimeMaxSec`, `PrivateTmp` or `ProtectHome`. `HOME` and `PATH` pass through to the agent by
  design; only Antigravity's bwrap confines them.
- Exact `agent-client-protocol==0.12.0` is justified (`acp_client.py:30-47` imports internals)
  but means security patches wait on a TaskSpindle release; `fastmcp>=3.3` is a floor below
  the version that introduced the load-bearing `run_in_thread` (`server.py:198-205`);
  `uvicorn>=0.30` is unbounded; `filterwarnings = ["error"]` turns any upstream deprecation
  into a suite failure.

## 3. The recovery subsystem is over-built

Provider refusal, quota, manual recovery, hybrid recovery and native extra usage together
occupy 14 of the 30 tables, 39 `Store` methods, and nine modules. There are fifteen distinct
state vocabularies (about 110 values), four independent single-use-claim state machines that
each check the other three (`runner.py:795-914`, `hybrid_recovery.py:319-345`,
`provider_recovery.py:347-363`), three divergent `_REFUSALS` sets, ten SHA-256 identity
schemes, and raw SQL executed against `store._conn` from outside the store
(`provider_recovery.py:249-399`, `hybrid_recovery.py:38-136, 367-423`).

The cost shows up on the consumer side: the Codex `work-pool` skill needs 546 lines, most of
them instructions for reading `capabilities` projections, to decide whether a provider may be
used. A single claim table with a `kind` discriminator and one refusal vocabulary would remove
the cross-checking and most of the projection surface.

## 4. Capability gaps

Verified absent, from the point of view of a Codex session orchestrating work:

- **No progress or streaming.** The only liveness signal is a 5 s heartbeat column; Codex polls
  `task_status` every 30 s. No `wait_for_task(ids, timeout)` blocking call, no partial text.
- **No retry for transport or timeout failures.** `TURN_TIMEOUT`, `ACP_SPAWN_FAILED`,
  `ACP_HANDSHAKE_FAILED`, `UNIT_START_FAILED` are terminal; `retryable` is recorded and never
  acted on. Hybrid recovery's 5/15/60-minute backoff applies only to provider refusals.
- **No pre-dispatch health probe.** A broken adapter is discovered after the lease and unit
  are taken.
- **No pagination.** `list_tasks` takes `limit` only (unvalidated); older tasks become
  unreachable.
- **No retention.** `cleanup_task` never removes `state/tasks/<id>/`; `events.task_id` has no
  `ON DELETE CASCADE` and the table has no-delete triggers (`store.py:222-239`), so a task can
  never be pruned.
- **No batch status, no task dependencies or priority** (dispatch is strictly by creation
  order, `orchestrator.py:1068`), **no structured attachments** beyond the prompt string, **no
  per-task token or cost ceiling**, **no provider failover** (by design: refusals name an
  alternative but never reroute), **no events/audit read tool**, **no diff of a prior
  revision**, **no non-systemd backend**, **no CPU/PID/wall-clock limits on worker units**.
- Second-class (configured ACP) profiles get no session mode, no sandbox and no per-task model
  selection, so Codex CLI or Gemini CLI cannot be added as an equivalent worker.
- Usage is partial: 54 of 183 turns have no usage row, and only Claude has a price table
  (`usage.py:53-63`).

## 5. What is good

The integration journal and `abort_staged`'s refusal to reset paths the candidate does not own
(`integration.py:298-306`); `merge-tree --write-tree` as a non-mutating probe; the alternate
`GIT_INDEX_FILE` for snapshots; the `--no-renames` reasoning in `collapse_candidate`; the
string-aware JSON extraction in `review.py`; a genuine end-to-end test in
`tests/test_orchestrator.py` over a real git repository and SQLite file; parameterized SQL
throughout the dashboard; `ReadOnlyStore` (`mode=ro` plus `query_only`) and the policy-store
authorizer that confines writes to two tables; a release workflow that verifies tag, wheel
version and changelog; ruff clean with zero `noqa`.

## 6. Remediation

### Tier 1 — applied on `audit-tier1`

| # | Change | Status |
| --- | --- | --- |
| T1 | Smoke test derives the tool count from `server.TOOL_NAMES` | done |
| T2 | Read-only tools reconcile but never dispatch; `_cycle` no longer masks the body's exception | done |
| T3 | `state_version` bumps only on transitions; dispatch, cleanup and worker bookkeeping writes use `update_task(bump_version=False)` | done |
| T4 | Failed worker unit is reset before an interrupted task is relaunched | done |
| T5 | Handshake/spawn failures carry a redacted stderr tail and its first line as the message; auth-context failure no longer masks the original refusal; `doctor` warns about symlinked Grok hooks | done |
| T6 | Dashboard read routes require a loopback `Host`; security headers on every response | done |
| T7 | Worker environment delivered through a 0600 `EnvironmentFile`, not `--setenv` argv; `cleanup_task` removes it | done |
| T8 | Version pins, `role` in the `usage_report` docstring, usage table columns, CLI fall-through, example config sections, undocumented subcommands | done |
| T9 | `node --test tests/web_ui` runs in CI | done |

### Tier 2 — recommended next

- Bounded retry for `TURN_TIMEOUT` and `ACP_*`/`UNIT_START_FAILED`, honouring `retryable` and
  the existing lease; report elapsed time in `task_status`.
- `wait_for_task(ids, timeout)` and `task_result` including the stderr tail.
- `list_tasks` cursor pagination; `cleanup_task` removes the task directory and snapshot refs
  (store the snapshot id); a `prune` CLI with events cascade.
- Default-deny `PermissionPolicy` with an explicit allowlist of read kinds; path confinement for
  writes; `_DELEGATION_WORDS` matched against tool names only.
- Pre-dispatch adapter handshake probe; ACP adapter smoke in CI.
- Version pins as a minimum plus advisory band; Grok/Antigravity price tables.
- One ISO-8601 parser; `record_integration` in a single transaction; reject
  `require_diff_retrieved` when `diff_size` is `NULL`; per-run verification timeout;
  `GIT_CONFIG_GLOBAL=/dev/null` for artifacts; `RuntimeMaxSec`, `TasksMax`, `CPUQuota` on units.
- Delete the dead Antigravity ACP path.

### Tier 3 — structural

- Collapse the four claim tables into one and the refusal vocabularies into one.
- Progress notifications over MCP; task dependencies; attachments.
- `ROOT_MUTATION` should ignore HEAD moves caused by TaskSpindle's own accepts.
- mypy or pyright; Python 3.13 in CI; pre-commit; dependency updates.

### Operational, outside the repository

- Re-deploy: the runtime Codex uses is 0.4.0 (schema 10); the repository is 0.5.0 (schema 11).
- Remove or replace the symlinked `~/.grok/hooks/guard-bash.json` so Grok can start its sandbox.
- Raise default review timeouts in the Codex skill to at least 900 s.
