## Findings worth remembering

- Grok 1.0.13 sends its turn summary on the JSON-RPC method `_x.ai/session_notification`, not
  `session/update`, and its own session log names the method differently. The ACP observer now
  accepts any `_<vendor>/…` method whose params are shaped like a session update.
- The Claude adapter 0.70.0 emits the turn's usage on the `session/prompt` response (ACP 0.12
  marks the field unstable) and forwards the SDK's `rate_limit_event` as `usage_update` with
  `_meta["_claude/rateLimit"]`. Failures arrive as JSON-RPC errors with `data.errorKind`.
- Claude Code writes the session record roughly 60 ms after the prompt response; the canonical model name
  still requires that file for the observed default configuration in adapter 0.70.0.
- The adapter takes its initial permission mode from the operator's `~/.claude/settings.json`
  regardless of `settingSources: []`; only `session/set_mode` changes it.
- Codex's `tool_output_token_limit` truncates MCP tool output silently; the model never sees
  that a page was cut.
